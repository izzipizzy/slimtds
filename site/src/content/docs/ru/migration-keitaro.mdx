---
title: Миграция с Keitaro
---

Если вы переходите с [Keitaro](https://keitaro.io/), большая часть привычного ложится на slimTDS напрямую — кампании, потоки, фильтры и S2S-постбэки имеют прямые аналоги. Эта страница переводит терминологию и проводит через перенос кампании. slimTDS намеренно уже Keitaro: это **single-tenant, self-hosted** маршрутизатор для органики и SEO-трафика, а не многопользовательская платформа с хостингом лендингов и интеграциями сеток. Понимание того, что **не** переносится, сэкономит сюрпризы.

## Соответствие понятий

| Keitaro | slimTDS | Примечание |
|---|---|---|
| Кампания | [Кампания](../campaigns/) | Точка входа; её slug — это боевой URL `/<slug>`. |
| Поток (stream) | Поток (flow) | Упорядоченные правила внутри кампании; побеждает первое совпадение. |
| Оффер | [Оффер](../core-concepts/#глобальные-офферы) | Офферы **глобальные** и переиспользуются между кампаниями через список целей потока. |
| Локальный лендинг | — (хостите сами) | slimTDS не хостит и не редактирует лендинги. Наведите оффер/редирект на URL вашего лендинга. |
| Фильтры | [Фильтры потока](../campaigns/#фильтры) | JSONB: AND внутри группы, OR между группами. Гео, устройство, боты, источник, время/IP. |
| Действия / тип редиректа | [Схема ответа](../core-concepts/#схемы-ответа) | 16 типов: 301–308, meta refresh, iframe, HTML/JSON/текст, curl-прокси, JS-редирект и др. |
| Сплит-тест / ротация | Веса офферов + [`{spin}`](../core-concepts/#spin--ротация-лендингов-внутри-одного-оффера) | Взвешенные, стабильные по посетителю доли офферов; `{spin}` — ротация лендингов внутри одного оффера. |
| Токены источника трафика | [Макросы](../core-concepts/#макросы) | `{click_id}`, `{utm_source}`, `{country}`, … подставляются в URL и постбэки. |
| `{subid}` / id клика | `{click_id}` | Идентификатор клика UUIDv7, который вы передаёте партнёру и получаете обратно в постбэке. |
| Фильтрация ботов (ISP/UA) | [Обнаружение ботов](../traffic-filtering/#обнаружение-ботов) | Слои IP · CIDR · ASN · ISP · User-Agent, обновляются ежедневно. |
| S2S-постбэк (входящий) | [Постбэки](../postback/) | `GET`/`POST /postback`; токены на оффер и общий токен уровня кампании. |
| Исходящий постбэк | [Исходящие доставки](../postback/) | Отвязанный outbox с ретраями по экспоненте. |
| Отчёты | [Статистика](../getting-started/#что-вы-получаете) | Партиционированные таблицы кликов/конверсий + дашборды. |
| Клоакинг ботов | Трэш-роутинг | Несовпавший трафик уходит в `trash_mode` + `trash_url` (включая ссылку `{offer:…}`). |

## Что отличается

- **Офферы глобальные.** В Keitaro оффер принадлежит кампании; в slimTDS у таблицы `core.offers` нет колонки `campaign_id`. Вы прикрепляете существующие офферы к потоку с весами, и один оффер может обслуживать много кампаний сразу.
- **Нет встроенных лендингов.** slimTDS маршрутизирует трафик; он не хостит, не редактирует и не A/B-тестит локальные лендинги, как Keitaro. Держите лендинги там, где они есть, и ссылайтесь на их URL — используйте [`{spin}`](../core-concepts/#spin--ротация-лендингов-внутри-одного-оффера) для ротации нескольких.
- **Single-tenant.** Один оператор или команда на инсталляцию, без ролей и многоаккаунтной панели.
- **Нет каталога сеток офферов и импорта по API.** Кампании, потоки и офферы создаются в админке (или сидируются); импортёра формата Keitaro нет.
- **URL по slug.** Кампания доступна по `/<slug>` (6-символьная Base58-строка или кастомный алиас), а не по ссылке кампании на отдельном домене.

## Шаги миграции

1. **Пересоздайте офферы.** Добавьте каждую цель как глобальный оффер с URL и выплатой. Переведите токены Keitaro в URL в [макросы slimTDS](../core-concepts/#макросы) (например, `{subid}` Keitaro → `{click_id}`).
2. **Создайте кампанию.** Дайте ей имя и, если хотите сохранить входящие ссылки, кастомный алиас по `^[a-zA-Z0-9]{3,16}$` в качестве slug.
3. **Перестройте потоки (streams) как flows.** Для каждого потока Keitaro добавьте flow, переведите его фильтры в группы фильтров, прикрепите целевые офферы с весами и выберите схему отдачи. Ставьте потоки от более специфичных к общим; последним оставьте catch-all с пустыми фильтрами.
4. **Настройте трэш-роутинг.** Сопоставьте поведение Keitaro «ни один поток не совпал» с `trash_mode`/`trash_url` кампании — при желании через [ссылку `{offer:…}`](../campaigns/#трэш-трафик), чтобы уйти на существующий оффер.
5. **Подключите постбэки.** Настройте партнёра вызывать [`/postback`](../postback/) slimTDS с `{click_id}`, который вы передали. Для исходящего S2S настройте шаблон исходящего постбэка с макросами.
6. **Перенаправьте трафик.** Обновите SEO-лендинги / источники на новый URL `/<slug>` (встройте [пиксель](../pixel/) на лендинги, чтобы получать события и [реплеи сессий](../replays/)).
7. **Проверьте.** Отправьте тестовые клики по гео/устройствам, убедитесь, что они попадают на нужный оффер, затем отправьте тестовый постбэк и проверьте, что конверсия появилась.

Поскольку массового импортёра нет, мигрируйте по одной кампании за раз и проверяйте каждую от начала до конца, прежде чем браться за следующую.
